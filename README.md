# Portfolio Compass — 專案管理儀表板公開展示

Kris Lu / Kamiyu Lab 的專案治理作品。以藍金視覺、6 個虛構專案與 18 項虛構工作，展示從團隊工作到管理決策的三種視角。

- 展示網站：https://kamiyu94.github.io/project-portfolio-demo/
- 個人作品集：https://kamiyu94.github.io/prototypes/
- 配套作品：https://kamiyu94.github.io/pmo-intake-demo/

## 體驗路徑

- **專案總覽**：進展、關聯工作與下一步；選擇呈報專案、調整順序、預覽 A4 報告並用瀏覽器列印／另存 PDF。
- **案件追蹤**：搜尋、部門／提案人／負責人／小組／狀態篩選與排序，查看虛構來源紀錄。
- **會議焦點**：到期與人工風險取較嚴重者，記錄下一步與需要協調事項，切換顯示停滯案件。

## 展示規則

- 日期預設固定為 `2026-10-26`，使用者可改「模擬今天」觀察燈號。7 天內到期至少黃燈、逾期紅燈；已完成案件不因期限升級。人工較高風險不會被自動降低。
- 超過 30 天未更新的未完成案件視為停滯。案件追蹤隱藏；會議頁預設隱藏，可切換；專案總覽仍包含。
- 專案完成度為有數值案件的等權平均，缺漏不視為 0；畫面標明有效樣本數。
- 修改只在瀏覽器 localStorage，不跨裝置共享。沒有正式帳號、公司資料連線、郵件、後端服務或即時同步。「來源」按鈕只開啟虛構紀錄。

這是依工作流程獨立重製的公開展示，沒有複製正式環境的資料、存取設定或排程。展示數字不是實際專案成效。

## 開發

原生 HTML/CSS/ES modules，無第三方執行時依賴。

```sh
npm test
npm run check
python3 -m http.server 4320 --bind 127.0.0.1
```

GitHub Pages 使用 `main` 分支根目錄。`assets/data.mjs` 定義虛構資料，`assets/model.mjs` 定義到期、停滯、排序與呈報順序規則。

## 閱讀與響應式排版

主要文字與表單以 16px（1rem）為基準，輔助文字 14px，小標籤至少 12px。字級使用相對單位；較窄螢幕改用單欄，寬表格在自己的容器內捲動。

## 活動型專案決策示範（2026-10-26）

`#decisions` 是另行設計的虛構活動情境，不代表客戶已採用。保留原有 6 個專案／18 項工作，另外展示四項活動工作：背板延遲、原訂夜間撤場、設備交付風險及待補人力資料。

- 工作拆解：完成條件、窗口、相依工作、原訂時程、最晚交付、完成預估與剩餘人時。
- 燈號：缺資料或超過 48 小時未更新為灰色；預估超出最晚交付為紅燈；延遲率達 20% 或緩衝消耗達 80% 為黃燈（可調）；無剩餘緩衝但仍有工作至少黃燈。其餘綠燈。模擬現在採畫面日期中午 12:00。
- 時間計算使用固定曆時，沒有工作日曆或自動推算相依排程。剩餘人時是工作量，不等同於工期。原訂完成與交付界線不隨追蹤修改。
- 決策：比較方案，記錄負責人、追蹤時間、理由與當時燈號；選定方案不自動轉綠。
- 執行追蹤：填寫結果、完成預估、剩餘人時與本次額外投入，重算燈號並保留歷程。零剩餘工時不代表正式驗收完成。
- 夜間撤場是原訂時段安排，即使綠燈仍可記錄人力安排。示範額外人時不是薪資計算或正式加班核准。
- `decision-model.mjs` 為規則與驗證，`decisions.mjs` 為畫面與獨立 localStorage。重設展示會一併重設決策紀錄與門檻。無帳號與後端，紀錄不具正式稽核效力。

## 員工回報與主管回應示範

從 `#employee` 開始，選擇示範承辦人／工作，可用「帶入示範回報」填入範例，再送出異常、交付影響、處理方案、預計解決時間、希望回應時間與支援需求。回報更新同一任務的完成預估，但保留原訂基準。

切換 `#decisions` 查看來源回報並回應（同意、調整、不採支援或請補資料），指定負責人與追蹤時間。回到員工頁可看到主管回覆，再回填執行結果。員工提請解除後，主管須確認燈號已回綠並填寫依據，才標記「異常已解除」；這不等同整項工作驗收。

回報狀態與風險燈號獨立，僅瀏覽或回應不會自動結案。補件與重新送出保留往返紀錄。狀態保存在原有決策工作台的 localStorage 中，新增 reports 欄位相容既有紀錄；「重設展示」會清除。角色切換只模擬同一頁面的兩個視角，沒有帳號授權、跨裝置通知、Google Sheet 或其他後端串接。`report-model.mjs` 定義回報驗證與狀態轉換。
